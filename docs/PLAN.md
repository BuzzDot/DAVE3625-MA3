**Nutrition-label OCR:** capture/upload a cropped nutrition label; a browser OCR worker such as Tesseract.js is a candidate for keeping images local. Blurred/uncertain values and “less than” entries need correction, not silent guesses. Local OCR still requires mobile performance/language-pack evaluation; server OCR would require explicit image upload consent, private transient storage and deletion. [Tesseract.js maintained project](https://github.com/naptha/tesseract.js).

Both flows must populate an editable **draft** and show units, original basis and source before saving. The user confirms/corrects each macro and serving weight, then chooses the consumed amount. Normalize known mass-based values to the existing per-100-g model: per-serving value × 100 / serving grams, then per-100-g value × consumed grams / 100. Example: 200 kcal per 50 g serving becomes 400 kcal/100 g; consuming 25 g records 100 kcal. Convert kJ to kcal only when needed using 4.184 kJ/kcal. Preserve unknown nutrients as null. Do not treat 100 ml as 100 g or infer an unknown serving mass; request a conversion/density or leave that basis unsupported in the initial slice. [Source basis fields](https://openfoodfacts.github.io/openfoodfacts-server/dev/explain-nutrition-data/).

Reuse food editing and SQL-calculated consumption snapshots after confirmation. An owner-protected capture-evidence record should retain the provider/barcode or OCR engine/basis/confidence plus user confirmation time; add that provenance to new historical snapshots through validated SQL. Keep user corrections separate from trusted shared catalog entries. The existing personal-food provenance guard means new evidence persistence needs a reviewed forward migration/server path, not `source` fields supplied by the browser. A first barcode proof of concept can start with typed barcode lookup into a reviewed personal-food draft, then add camera decoding; label OCR follows after basis conversion tests. Validate re-scans, missing products, per-serving conversions, unknown fields and unchanged historical totals. No new packages, endpoints, image uploads or schema changes are authorized now.
